# Workspace AI 공통 컨텍스트 예시

이 규칙은 `WORKSPACE_HARNESS_ROOT`로 지정한 작업 공간 아래에서만 적용한다.

## 공통 작업 방식

- 작업 시작 시 git 루트·브랜치·dirty 상태를 확인하고 기존 사용자 변경을 보존한다.
- 레포의 `AGENTS.md` 또는 `CLAUDE.md`에 정확한 검증 명령이 있으면 우선한다.
- 비밀 파일과 실제 자격증명은 명시적으로 필요한 경우가 아니면 읽거나 출력하지 않는다.
- 소스 변경 후 관련성이 가장 높은 타입체크·테스트·빌드를 실행한다.
- 커밋·푸시·PR·배포는 사용자가 요청한 경우에만 수행한다.

## 레포 인덱스

자신의 프로젝트 경로, 스택, 배포 방식과 브랜치 규칙을 여기에 기록한다.

| 레포 | 경로 | 검증 | 브랜치 규칙 |
| --- | --- | --- | --- |
| example-web | `projects/example-web` | `npm test && npm run build` | PR로 `main` 병합 |

## 옵시디언 볼트

볼트를 사용한다면 `OBSIDIAN_VAULT_PATH`를 설정한다. 프로젝트 상태가 실제로 바뀐 경우에만
관련 노트의 다음 할 일을 갱신한다.
